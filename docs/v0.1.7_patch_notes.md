# CharInfo Manager v0.1.7 — Stabilization + Reunification

> Status: Ready for release. Core implementation, workspace cleanup, final cross-mode browser regression, Creator Preview lifecycle checks, and live image-fallback timeout validation are complete. The current branch passes the full automated baseline; only Git release closeout remains.

## Highlights

- Reunified Viewer and Creator Manager into one installable CharInfo Manager script while keeping their source responsibilities separated.
- Stabilized Viewer routing, read-only data boundaries, DX production isolation, image fallback, Save behavior, and current-character refresh.
- Added a real Creator Viewer preview for unsaved drafts and a controlled workflow for applying saved visual data to the current chat.
- Finished the Special NPC desktop redesign and the main mobile redesign, including responsive navigation, panel organization, wallpaper behavior, and readable skill/holding layouts.

## Architecture and lifecycle

- Viewer and Creator now ship as a single user-facing script/bundle.
- Viewer, Creator, shared services, and runtime remain separate internal modules.
- Removed the host bridge that existed only for cross-script communication; Viewer talks to Creator through a narrow in-bundle controller API.
- Creator Editor mounts only when opened and is destroyed when closed instead of remaining resident.
- Viewer-owned character libraries, worldbook entry toggles, and runtime state remain outside Creator.

## Routing and data safety

- Trusted DX mode is granted only through the controlled DX placeholder + loader path; name matches, metadata, normal profiles, or hand-written fields cannot upgrade a character into DX.
- Special NPC mode is granted only by the matching CharInfo visual profile (`char_info.profiles[姓名]`) or the temporary compatible `char_info_visuals[姓名]` path.
- Direct image URLs or legacy image syntax inside `<char_info>` no longer silently grant Special NPC mode.
- Viewer Runtime no longer migrates legacy `status.externalGalleries` back into CharInfo profile data; Viewer remains read-only.
- Current NPC text/quote overlays now preserve the character's Special NPC visual identity instead of accidentally falling back to the normal layout.

## DX production isolation

- Development/watch builds can still use the real DX implementation for local testing.
- Production builds physically replace the DX implementation with the stable disabled adapter rather than merely disabling it at runtime.
- Added regression coverage to prevent DX registry/private identifiers from leaking into public production output.

## Save and import fixes

- Special NPC Viewer keeps the player Save action on both desktop and mobile.
- Save can write to either the chat MVU character state or the current chat worldbook.
- Saving to the chat worldbook writes clean YAML content without wrapping it in `<char_info>`.
- YAML flow-mapping style tags are normalized back into readable values before MVU writeback instead of becoming `[object Object]`.
- Save feedback now follows the real operation result instead of relying on unrelated variable-update events.
- If the underlying API Promise remains pending after the data is already written, read-back verification can complete the Save state correctly.
- The Save UI now transitions from loading to success/failure instead of remaining stuck on “saving”.

## Image loading and fallback

- Creator Preview and Special Viewer now advance through `sources[]` in order when a source errors, times out, or fails and the user retries.
- Fallback wraps only after all sources have been exhausted.
- Creator supports reordering fallback sources so the author can explicitly control URL0 / URL1 / later priority.
- Added optional image-fallback debug logging for source index, URL, error, timeout, fallback, loaded, and all-failed states.
- Static Catbox character images and Creator previews now retain the author's original URL instead of being unnecessarily rewritten through `wsrv.nl`, allowing normal browser/CDN cache reuse.
- Dynamic media paths remain compatible with GIF/APNG/animated WebP/video handling.

## Creator Manager

- Creator can mount the real Viewer as a read-only preview of the current unsaved draft.
- Draft preview uses the current colors, entrance quote, gallery, and complete fallback-source ordering without writing to chat variables or worldbooks.
- Preview does not activate DX import side effects or borrow another character's visual profile.
- After saving, Creator can explicitly apply the saved managed CharInfo block to the current chat by evaluating only the verified managed EJS fragment, persisting variables, verifying the result, and forcing a CharInfo refresh.
- Creator media preview behavior was stabilized so animated/video sources have a visible preview state instead of appearing unloaded.
- Editor step layout was stabilized so the editing window does not keep changing height between steps.

## Current-character refresh

- The current-character library refresh action now performs a real CharInfo Force Refresh.
- It rereads the latest MVU snapshot and chat variables, then performs controlled teardown/remount of active CharInfo floors.
- Refresh does not implicitly execute arbitrary worldbook EJS.
- Applying saved Creator data reuses the same Force Refresh path.

## Special NPC — desktop

- Finished the desktop overview/panel layout and interaction pass.
- Reordered navigation so `面板` is the second tab.
- Moved HP / SP / MP out of the overview and into `面板`.
- Rebalanced the overview hierarchy and spacing around name, identity, level/life tier, attributes, and entrance quote.
- Increased the entrance quote area.
- Restored taller/slimmer five-attribute flags and adjusted the number position inside each flag.
- Desktop Save feedback and both write targets were verified in the current SillyTavern workflow.

## Special NPC — mobile

- Rebuilt the bottom structure into six stable navigation items plus a dedicated compact Save action instead of letting Save wrap into a broken second row.
- Mobile overview now focuses on the portrait, entrance quote, and character name.
- Level, life tier, race, identities, occupations, five attributes, and HP/SP/MP were moved into `面板`.
- Detail pages use the player's currently selected portrait as a semi-transparent wallpaper.
- When multiple portraits exist, entering a detail page keeps the last portrait the player actually viewed instead of jumping back to image0.
- Detail wallpaper is captured as a static frame, so animated images/video stop moving while reading profile information.
- `技能` received mobile-specific readable typography, hierarchy, line spacing, background support, and stable side gutters without rewriting or semantically interpreting character data.
- Skills are grouped as active → passive → other while preserving the author's original order inside each group; type is encoded by stable symbols while color remains reserved for rarity.
- Skill and holding groups use bordered, independently collapsible panels that default to expanded, with CSS-drawn chevrons and hidden internal scrollbars that keep wheel/touch scrolling functional.
- `持有` received the same mobile readability/gutter treatment while keeping its own equipment/item structure and separate equipment/item grouping.
- `登神` retains a compact vertically scrollable mobile layout.
